# 鴈行・對戰

中國戰略思想史課堂用立體兵棋。讀物：曾瑞龍〈鴈行陣是什麼樣子？〉（2008）。

主畫面有三個入口：

- **教學模式**（`teach.html`）：一個人玩，八個抉擇，約 5～8 分鐘。
- **對戰模式**：全班分成藍軍（攻方・鴈行陣）與紅軍（守方・方陣），各派一人用手機下令，五個回合。
- **練習：和電腦對打**：一個人選一方，電腦扮演另一方。

## 課堂流程

1. 老師打開網頁，按「對戰模式：開一局新推演」，出現全螢幕的 QR 碼頁（一次顯示一隊，藍軍、紅軍、投影畫面輪流切換）。
2. 兩隊各派一人掃碼。每隊第一位掃碼的人是指揮官；同隊其他人掃碼只能觀看，必要時可按「改由我指揮」。
3. QR 碼頁下方開「老師裁判畫面」（老師自己看，不要投影）與「投影畫面」（給全班看）。
4. 雙方送出命令後，老師按「結算本回合」（或勾選「雙方都送出後 3 秒自動結算」）。某一隊缺席時，可以勾「由電腦下令」。
5. 結束後，各畫面出現戰後檢討與「揭曉與討論」。

## 各方看得到什麼

- 藍軍看不到紅軍預備隊這一回合的位置，只看到斥候回報（晚一回合）。
- 紅軍看不到藍軍「向中部集中」；派人試探、或藍軍猛攻的那一回合，才看到中部後方有多厚。
- 投影畫面只顯示雙方都知道的事，結束後全部揭曉。
- 老師裁判畫面看得到全部。

## 測試用連結

- 單機模式：網址加 `&local=1`，同一台電腦、同一個瀏覽器的分頁直接互通，不經過網路資料庫。
- 例如：`?role=ref&room=TEST&local=1`、`?role=blue&room=TEST&local=1`、`?role=red&room=TEST&local=1`、`?role=proj&room=TEST&local=1`。

## Firebase 設定

沿用 drone-swarm-class 專案，資料存在 `goose/` 路徑下。在 Realtime Database 的「規則」頁加上：

```json
"goose": { ".read": true, ".write": true }
```

原有的 `rd`、`sr`、`hong` 不要動。

## 檔案

- `rules.js`：規則（純邏輯，瀏覽器與 node 共用）
- `ai.js`：電腦對手（典型打法與「會判斷」的電腦）
- `review.js`：依這一局實際的命令自動產生戰後檢討
- `world.js`：立體戰場（畫風：黃昏平原／全息推演室；周邊地形：疏林草甸）
- `app.js`：主畫面、QR 碼頁、裁判、指揮、投影、練習、揭曉頁、連線
- `config.js`：Firebase 設定（設成 `null` 即為單機模式）
- `teach.html`：教學模式（單人版）
- `test.js`：規則測試（`node test.js`）

規則與驗證的完整說明見專案文件〈鴈行對戰_規則表與驗證〉。
